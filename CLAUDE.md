# Innistrad Horrors: notes for Claude

Innistrad Horrors (called Ashen Depths until round 15) is a Diablo-style isometric action RPG themed on Magic: The Gathering (round 13) in **Godot 4.3** (GDScript, GL Compatibility
renderer). It is Petr's project; he describes features in plain language and expects them built,
tested and shown with screenshots. `README.md` is the player-facing guide (controls, areas, rules,
file map) and must stay accurate when gameplay changes. `docs/HISTORY.md` has every request Petr
made so far and what was built for it; read it before planning bigger work.

## Repository layout

## Running and testing (cloud or Linux)
- `tools/setup_godot.sh` installs Godot 4.3 as `~/.local/bin/godot` and imports the project. In Claude
  Code cloud sessions the SessionStart hook in `.claude/settings.json` runs it automatically.
- `tools/smoke_test.sh [dir]` runs `scripts/autotest.gd` under `xvfb-run` (about 2 minutes, software
  rendering, so the fps it prints is meaningless). It visits the town, tests inventory clicks and the
  trader, fights on the moor, loads every area, kills the act boss, dies and revives, and saves
  screenshots. A good run ends with `AUTOTEST done` and has no `SCRIPT ERROR` lines. The ALSA audio
  errors and "RIDs leaked" warnings at exit are normal in a headless container.
- Run the smoke test after every change and look at the screenshots it saves (Read the PNGs). When a
  feature isn't covered, extend `autotest.gd` with a step and an `AUTOTEST ...` print line.
- `tools/export_web.sh` builds the browser version into `build/web/` (git-ignored, about 65 MB). It
  uses the no-threads web template, so any HTTPS host works without special headers.
  `tools/export_web.sh --threads` builds the multi-threaded one into `build/web-mt/` (preset "Web Threads");
  it needs the page served with COOP `same-origin` and COEP `require-corp` (the shop does this). Petr hosts it on
  his own website; give him the folder as a zip.
- Frame rate: `xvfb-run -a godot --path . --rendering-driver opengl3 --resolution 1920x1080 -- --bench --area=1`
  (add `--web` for the browser build's settings, `--off=post,lights,...` to see what something costs,
  `--seed=N --shot=x.png` for a screenshot of the same map layout to compare before and after).
  Software rendering, so compare runs with each other, never with real hardware.
- Static check without running: `godot --headless --path . --check-only --script res://scripts/x.gd`.

## Art pipeline
Everything visual is generated from code; there are no hand-made image assets.
- Characters: low-poly 3D models built in `tools/models.gd`, baked by `tools/bake_sprites.gd`:
  `xvfb-run -a godot --path . --rendering-driver opengl3 --script res://tools/bake_sprites.gd`
  (add `-- --only=hero,brute` to bake some, `-- --preview` for a still lineup), then
  `python3 tools/finish_glow.py`. Sheets: columns are frames, rows are `animation * 8 + direction`.
- Each hero is its own body layer (`base_ajani`, `base_chandra`, `base_liliana`) over one shared
  skeleton, plus one sheet per gear layer (helms, armour weights, gloves, belt, boots, shields, weapons),
  cut so they stack in a fixed order. Gear is cut by a plain human body (layer `human`, never baked on
  its own) so it fits all three heroes. Worn items tint their layer. Keep this when adding gear: Petr
  explicitly wants equipped items to change how the hero looks. Preview a hero with gear:
  `-- --preview --only=hero:ajani+armor_heavy+weapon_axe`.
- `finish_glow.py` processes every `_glow.png`, so after baking only some monsters restore the glow
  sheets of the others with `git checkout -- sprites/<type>_glow.png` (running it twice dims them).
- Monster ranks recolour sprites through `shaders/rank.gdshader` with `Game.RANK_TINTS`.
- Item inventory pictures are painted procedurally in `scripts/item_art.gd` from each item's seed,
  so two items of the same base look slightly different (Petr asked for this).
- Ground and wall textures: `python3 tools/gen_textures.py` (needs Pillow and numpy).

## Design rules Petr set (keep them)
- Diablo II is the reference for feel and rules, including the skill system (round 14 replaced the
  Diablo III one at Petr's request). Never use Blizzard
  names or assets. Since round 13 the theme is Magic: The Gathering: heroes are planeswalkers, monsters
  are MTG creatures, bosses and sub-bosses are MTG legends, skills may use MTG card names. The game will
  have five acts, one per colour; Act I is black (swamp). Wizards' Fan Content Policy needs written
  permission for games; Petr was told and on 2026-10-13 chose to publish it anyway as a free fan game.
- Heroes (`Player.CLASSES`): Ajani (Barbarian stats), Chandra (Sorceress), Liliana (Necromancer).
  Skills are data in `scripts/skills.gd`, Diablo II style: 3 trees x 10 skills per hero on rows opening
  at levels 1/6/12/18/24/30, prerequisites, 1 skill point per level, up to 20 per skill, growth per point
  (`per`) and damage synergies (`syn`), passives, +skills from gear. Everyone uses mana. Left and right
  mouse skills; keys 1-4 swap the right one. `Player.use_skill` runs them by `kind`; add a skill by
  adding data, and a new kind only when no existing one fits.
- Act I is fixed: town, then 8 areas always in the order open, open, dungeon, dungeon, open, open,
  dungeon, dungeon, with fixed names (`scripts/act.gd`). Each area's shape is regenerated from its
  own seed every run. Open areas are wide with landmarks that give them a profile (rocks, buildings,
  ponds, trees); dungeons are narrow (caves, crypts, building interiors).
- Every area has a waypoint; the waypoint list includes the town and every waypoint found so far.
- Monster difficulty is a **rank** (1-12) that rises through the act and scales life, damage,
  defense, attack rating and xp. 15 base monster types; colour shows rank. Ordinary packs sometimes
  contain higher-ranked monsters; each area has unique sub-bosses and an end boss several ranks
  higher with a large escort, which seals the exit until killed.
- Hero stats (Strength, Dexterity, Vitality, Energy) and the hit and block formulas follow Diablo II
  exactly; look up the original rule when adding a stat-driven mechanic.
- Items: level/Strength/Dexterity requirements, many affixes, normal/magic/rare/unique, charms that
  work from the inventory, slots for helm, amulet, armour, weapon, shield, gloves, belt, boots and two rings.

## Code conventions
- GDScript with tabs, static types where the surrounding code has them, `##` doc comments at the top
  of each script saying what it does. Short, plain comments; match the file you are editing.
- Data lives in `const` dictionaries/arrays near the top of the script that owns it (`Act.AREAS`,
  item bases and affixes in `items.gd`, monster kinds in `monster.gd`).
- Most nodes are built in code rather than in `.tscn` files; follow that.
- Draw calls are what the browser pays for. In `_draw`, each `draw_polygon`, `draw_colored_polygon`,
  `draw_circle` and antialiased `draw_line` is its own draw call; triangle `draw_primitive`s with the
  same texture batch. Draw quads with `Game.quad` (a 4-point primitive doesn't come out as a quad in
  4.3) and call `Game.begin_batch` before a run of primitives whose texture differs from the previous
  run (4.3 keeps the first texture of a primitive batch). Props draw everything from `Game.prop_atlas`.
- Graphics quality `Game.quality` (LOW, MEDIUM, HIGH; L cycles it, saved in `user://settings.cfg`,
  applied in `Main._apply_quality`). HIGH: full resolution, `post.gdshader` (`post_bloom_web.gdshader`
  in the browser, which has no screen mipmaps). MEDIUM (the browser's default): base 1280x800 scaled up,
  `post_medium.gdshader`. LOW: also drops shadows, light twins, monster lights, normal maps and embers,
  `post_low.gdshader`; lights made with `Game.make_light_pair` follow it automatically. The web build
  (`Main.web`: `OS.has_feature("web")` or `-- --web`) drops to LOW once by itself if play starts slow. Test web-facing changes with `tools/export_web.sh`
  and a headless Chromium load (Playwright is preinstalled in cloud sessions).

## Known gaps and ideas Petr was offered
- Difficulty has only been tuned by the automated test, not by hand; the act boss has 1,864 life.
- Within a game an area keeps its living monsters and ground loot (`area_state`); a saved hero
  continues as a new game (`Main.reset_act`), like Diablo II (round 17).
- Saves (round 16): one hero per planeswalker. A new field worth keeping goes in `SaveGame.snapshot`
  and `restore`; bump `SaveGame.VERSION` only with a conversion for old saves, or players lose heroes.
- No Acts II-V, no quests, no skill respec. Skill numbers are untuned beyond the smoke test.
- Monster models were restyled after MTG creatures in round 13 (rats, vampires, Phyrexians, demons,
  beetles, black knights, specters, the angler); Sheoldred still uses the demon model.
- Models are low-poly; more detail in `tools/models.gd` plus a rebake is the cheap visual upgrade.
- The web build needs a desktop browser with keyboard and mouse.
